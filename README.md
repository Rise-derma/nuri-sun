# ぬりサン! ☀️ 光老化よぼうアプリ — 公開マニュアル

日焼け止めの塗りわすれを防ぎ、**光老化(ひかりろうか)**という言葉を広めるための教育用ウェブアプリです。非商用・教育目的で公開し、特定の企業・教室・製品の販促には使用しません。

このファイルをアプリと一緒にGitHubへアップすると、リポジトリのトップにこのマニュアルが表示されます。

---

## 1. このアプリの特徴

* **インストール不要** — iPhone・Android・PCのブラウザで開くだけ
* **記録データは端末の中だけ** — きろく・きせかえ・設定はブラウザ内に保存され、外部へ送信されません。位置情報を許可した場合だけ、UV予測取得のため丸めた緯度・経度をOpen-Meteoへ送信します
* **アカウント登録なし** — 名前やメールアドレスの入力は一切ありません
* **静的ファイルだけ** — サーバー処理やAPIキーは不要。アプリ本体と同梱の地域境界データだけで動き、遠隔の実行用スクリプトは読み込みません
* **外部の音源なし** — 通知音はWeb Audio APIでその場で作る独自の合成音です。外部の音源・楽曲・音声素材は使用していません

### 主な機能

| 機能 | 内容 |
|---|---|
| ぬった!ボタン | タップで記録、塗りなおしタイマーが開始(2/2.5/3時間から選択) |
| おしらせ | 時間になると画面の色が変わり音が鳴る(夜18時〜朝6時はおやすみ) |
| UV表示 | 位置情報を許可すると現在地の気象モデルによる予測値(Open-Meteo)、なければ気象庁資料を参考に単純化した地域別・季節別の目安 |
| 光老化よぼうコイン | 最初の3回は顔のパーツ、4回目以降は1枚(たまにボーナスで3枚・5枚)。ホームに枚数を表示 |
| 段階かいほう | 累計獲得枚数が増えると、交換できるパーツが少しずつ増える(8枚ごとに約6個) |
| きせかえ | キャラ6体を含む58パーツ・12カテゴリ。コインでパーツと交換し、自由に着せ替え |
| ずかん | 集めたパーツのコレクション |
| きろく | れんぞく日数・さいこうきろく・こんげつの回数・るいけい・2週間の履歴 |
| サンケアのヒント | 21本(公的資料と一般的なサンケア情報にもとづく教育用の短文) |

### 表記のルール

子ども向けの画面本文に出る漢字は**小学1〜3年生で習う範囲**に限定しています。唯一の例外が「**光老化**」の「老」(小4)で、これはアプリの啓発テーマそのものであるため、ヘッダーにふりがなを付けて使用しています。サービス名・ライセンス名・リンク先名称は原表記を使用します。

## 2. 公開手順(約10分)

### 用意するもの

* GitHubアカウント(無料。 https://github.com で登録)
* 配布ZIPを展開した中の `index.html`、`region-data.js`、この `README.md`

**GoogleアカウントもAPIキーも不要です。** サーバー側の準備は一切ありません。

### STEP 1 ZIPを展開する

配布ZIPには、GitHub Pages用の **`index.html`** と地域判定に必要な **`region-data.js`** が入っています。2ファイルは同じフォルダに置いたまま使います。

### STEP 2 GitHubにアップロードする

1. https://github.com にログイン
2. 右上の **「+」→ New repository**
3. Repository name に `nuri-sun`(自由)、**Public** を選んで **Create repository**
4. **「uploading an existing file」** をクリック → ZIP内のファイルと `.github` フォルダをまとめてアップロード → **Commit changes**

> **公開名義について**: Open-Meteoの無料APIは非商用利用向けです。既存アカウントの名称・プロフィールが企業キャンペーンや販促を示す場合は、そのアカウント直下ではなく、中立名の無料Organizationを作って公開してください。公開ページやリポジトリから商品・店舗・購入先へ誘導しないでください。

### STEP 3 GitHub Pages を有効にする

1. リポジトリ上部の **Settings → 左メニューの Pages**
2. Build and deployment の Source を **Deploy from a branch**
3. Branch を **main / (root)** にして **Save**
4. 1〜3分待ってページを再読み込みすると、公開URLが表示されます

```
https://あなたのユーザー名.github.io/nuri-sun/
```

> **https について**: 現在地のUV予測表示に使う位置情報は、セキュリティ上 https のページでしか動きません。GitHub Pages は自動的に https になるのでそのままでOKですが、PCで `index.html` を直接ダブルクリックして開いた場合(`file://`)は地域別の目安表示のままになります。動作確認は公開URLで行ってください。

## 3. 公開後の動作確認(5分)

公開URLをスマホで開いて、順に確認します。

1. アプリが表示され、ヘッダーに「ぬりわすれゼロで光老化(ひかりろうか)をふせごう」が出る
2. 初回説明を読んで「はじめる!」を押す → その後に位置情報を「許可」→ UVカードのバッジが**「ちいきべつ」→「いまのよそう」**に変わる
3. 「ぬった!」を1回押す → 最初のパーツ(め)がもらえ、報酬画面が開く
4. 報酬を閉じて**きせかえ**タブを開く → もらったパーツが表示される
5. ページを再読み込み → 1回目のきろくとパーツが残っている
6. もう一度「ぬった!」を押す → 「さっきぬったばかりだよ」と出る(30分の連打防止)
7. 設定で「データをぜんぶけす」を2回押す → 初回説明に戻る

2・3回目のパーツと4回目のコインまでを手動で確認するには、各記録の間を30分以上あけるため約90分かかります。この一連の進行、コイン交換の2回タップ、着せ替えは自動テストでも確認しています。

## 4. スマホでアプリのように使う

ホーム画面にアイコンを追加すると、ワンタップで開けます。

* **iPhone(Safari)**: 画面下の共有ボタン(□↑)→「ホーム画面に追加」
* **Android(Chrome)**: 右上のメニュー(︙)→「ホーム画面に追加」

おしらせ(色の変化と音)は、アプリの画面を開いているあいだだけ動きます。ブラウザの自動再生制限により、ページを開き直した後は、音を使えるようにするため画面を一度タップする必要があります。

## 5. 更新のしかた

GitHubのリポジトリで `index.html` を開き、右上の鉛筆マーク(Edit)→ 修正 → **Commit changes**。または修正済みファイルを同じ名前で再アップロードしても上書きされます。`region-data.js` は地域判定に必要なので削除しないでください。数分で公開URLに反映されます。

### パーツを追加したいとき

`index.html` 内の `const PARTS = [` の中に、**1行足すだけ**でガチャ・ずかん・きせかえの3か所に自動反映されます。

```js
{ id:'hat-newitem', cat:'hat', n:'あたらしいぼうし', r:1, svg:'<path d="..." fill="#FFB300"/>' },
```

* `cat` は12カテゴリのいずれか(base / bg / ray / wear / cheek / eye / mouth / glasses / neck / hat / hand / fx)
* `r` はレア度1〜3(コインの値段: ★1=1枚 / ★2=3枚 / ★3=6枚。4は達成報酬専用で購入不可)
* かいほうの順番は自動計算されるため、追加しても設定不要(レア度の低い順・カテゴリ交互)
* `svg` は 120×120 の座標系で描く

### ヒントを追加したいとき

`const TIPS = [` の中に1行足します。表示スペースの都合で**58字以内**を目安にしてください。

## 6. トラブルシューティング

| 症状 | 対処 |
|---|---|
| バッジが「ちいきべつ」のまま | ①https の公開URLで開いているか(`file://`は不可) ②位置情報を許可したか ③Open-Meteo側の一時的な障害(その間は自動で地域別の目安表示になります) |
| 「ちいきデータをよみこめなかった」と出る | `index.html`と`region-data.js`を同じフォルダへ置き、GitHubへ両方アップロードしてください。復旧までは設定から地域を手動で選べます |
| きろくが消えた | きろくは端末×ブラウザごとの保存です。シークレットモードや「閲覧データを削除」で消えます。別のブラウザで開くと別データになります |
| 「ほぞんできない」と出る | プライベートブラウズ等で保存機能がブロックされています。通常モードで開いてください |
| おしらせが鳴らない | 画面を開いたままにし、開き直した後は画面を一度タップしてください。閉じている間の通知はできません。また夜18時〜朝6時は鳴りません |

## 7. データとプライバシー

* きろく(れんぞく日数・るいけい回数・履歴)、きせかえ、せっていは、**すべて利用者の端末内にのみ保存**されます
* 名前・メールアドレス等の個人情報は**一切収集しません**(入力欄がありません)
* アプリの機能が追加で行う外部API通信は、**UV予測値の取得(Open-Meteo)のみ**です。位置情報を許可しない場合はこのAPI通信も発生しません(ページ本体は公開先のGitHub Pages等から読み込まれます)
* 位置情報を許可した場合、緯度・経度を送信前に**小数2桁(およそ1km単位)へ丸めて**Open-Meteoへ送信します。正確な位置情報は、このアプリの保存データには残しません
* Open-Meteoは、無料APIの運用・トラブル対応のため、IPアドレスや位置座標を含む場合があるWebサーバーログを保持し、90日後に削除すると説明しています。詳細は[Open-Meteo Terms & Privacy](https://open-meteo.com/en/terms)を確認してください
* アプリ独自の利用者IDは使用せず、利用者の行動を外部で集計するアクセス解析も組み込んでいません

学校・教室・保護者への案内でも、この点をそのまま説明できます。

## 8. 利用しているサービス

| サービス | 用途 | 条件 |
|---|---|---|
| GitHub Pages | ホスティング | 公開リポジトリは無料 |
| Open-Meteo | 現在地のUV予測値の取得 | APIキー不要。無料APIは非商用利用向けの利用上限と、CC BY 4.0の表示条件あり |
| 気象庁「紫外線のデータ集」 | 位置情報を使わない地域別・季節別目安の参考 | 気象庁サイトへのリンクと、アプリ用に単純化した値であることを表示 |
| 国土交通省「国土数値情報 行政区域データ N03-2025」 | 現在地から8地域を判定する同梱境界データ | アプリ用に境界を簡略化。出典をREADMEとデータファイル内に表示 |

本アプリは広告・購読料のない非商用・教育目的での公開を前提としています。Open-Meteoは、この用途を無料APIの非商用例として挙げています。利用上限や規約は変更される可能性があるため、公開後も[Terms & Privacy](https://open-meteo.com/en/terms)を確認してください。**販促目的や商用サービスとして提供する場合は、Open-Meteoの商用ライセンスが別途必要です。**

なお、Open-Meteoが返す「現在のUV」は観測機器による実測値ではなく、気象モデルにもとづく予測値です。アプリ内でも「いまのよそう(予測値)」と表記しています。

アプリでは、Open-MeteoのUV値を表示用に小数1桁へ丸め、UVの強さを分類しています。この変更をアプリ画面上に明記しています。

### 主な参考資料

* [Open-Meteo Licence](https://open-meteo.com/en/licence) — 現在地のUV予測データ、CC BY 4.0
* [気象庁「紫外線のデータ集」](https://www.data.jma.go.jp/env/uvhp/info_uv.html) — 月別・地域別のUVインデックスの傾向
* [国土交通省「国土数値情報 行政区域データ N03-2025」](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-2025.html) — 端末内の地域判定に使う簡略化境界の原資料
* [環境省「紫外線環境保健マニュアル2020」](https://www.env.go.jp/content/900410650.pdf) — 紫外線の健康影響と対策
* [日本皮膚科学会 皮膚科Q&A「日焼け」](https://qa.dermatol.or.jp/qa2/) — SPF・PA、使用量などの一般的説明

地域別のUV値は、気象庁資料の季節・緯度による傾向をアプリ用に8地域へ単純化した概算値です。地域の自動判定には、国土数値情報の2025年行政区域を簡略化した同梱境界を使います。境界付近や島しょ部では誤差があり得るため、設定から手動変更もできます。

## 9. 自動テスト(任意)

公開時に実行に必要なのは `index.html` と `region-data.js` です。開発時の回帰テストを再実行する場合は、Node.jsがあるPCで同梱のテスト一式を使います。

```bash
npm ci
npm test
npm run test:browser
```

`npm test` は通常回帰39項目、堅牢化回帰68項目、不具合回帰17項目、追加故障注入11項目の**計135項目**を実行します。保存の読込・書込・容量不足、複数タブの同時更新、旧データ移行、行政区域1,902代表点、壊れた地域境界、海外座標、位置権限の取り消し、Open-Meteoのログ保存説明と公式リンク、30分更新、古い・形の崩れたUV応答、時計の巻き戻し、夏時間の春・秋切替、壊れた保存データ100パターン、`__proto__`混入、購入、音声失敗、色コントラスト、漢字監査などを含みます。

`npm run test:browser` はChrome/Chromiumで**198項目**を実行します。280×653〜2560×1440の画面、短い横向き画面、文字200%拡大、位置情報許可前のプライバシー説明、実localStorage読込失敗・容量不足と復旧、全タブ、設定、モーダル、報酬の連打・遅延取消、Web Locksあり/なしの複数タブ実競合、地域データ欠落・内部破損、セーフエリア、タッチスクロール、キーボードフォーカス、axeによるWCAG違反検査を含みます。配色は別の数値テストでも確認しますが、これはアクセシビリティ適合の認証ではありません。実機固有の位置情報許可画面と音声出力は、公開前にスマートフォンでも確認してください。

テストはWindows・macOS・Linuxの一般的なChrome/Chromiumの場所を自動検出します。見つからない場合は、実行ファイルの絶対パスを環境変数`CHROME_PATH`に指定してください。

同梱の `.github/workflows/qa.yml` により、GitHubへ変更を送るたびに上記333項目を自動実行できます。
